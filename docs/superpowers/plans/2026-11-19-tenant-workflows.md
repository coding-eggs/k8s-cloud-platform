# 租户交付与日常运维实施方案

按下表顺序独立交付。接口名与新增字段均为实施建议，现有调用方可继续使用原接口。每期先完成数据与权限迁移，再发布服务端和页面。

| 阶段 | 用户入口 | 交付完成的标志 |
|---|---|---|
| 一 | 流水线运行详情 → 应用发布 | 能发布指定构建的镜像，并从发布版本追溯到构建 |
| 二 | 告警详情 → 相关资源、规则或事发日志 | 值班人员按告警对象排障，下一班能看到处理记录 |
| 三 | 租户总览 → 开通空间或提高已有空间配额 | 成员能进入获批空间，也能看到已有空间扩容的实际结果 |
| 四 | 全局搜索 → 资源详情 | 输入资源名即可在授权范围内找到并打开正确对象 |

## 一、将构建产物用于应用发布

**改动起点。** `k8s-core` 的 `ImagePushNode` 已用 Buildah 将推送摘要写入共享工作区的 `.image-digest`。同次运行可以有多个推送节点，共享文件无法可靠区分并行产物。`PipelineRunFinisher` 已在清理集群对象前调用归档服务。`AppReleaseRequest.images` 目前接收服务到 tag 的映射。

- [ ] 在推送节点的 Tekton Task 声明镜像引用和摘要两个 result。推送成功后将实际展开的仓库、tag 和本节点的摘要写入该 Task 自己的结果路径。保留原工作区文件供已有流水线脚本使用。通过 TaskRun 与流水线节点的对应关系采集结果，覆盖并行、屏蔽和断点重试场景。
- [ ] 扩展运行快照与 `PipelineArchiveService`。新增产物表，以运行 ID 和节点 key 唯一，保存仓库、tag、digest 及可确认的源码修订。归档重投复用原记录；缺少可信摘要的节点显示原因。重试只归档本次实际推送的产物。通过原有运行详情接口返回产物列表，旧记录返回空列表。
- [ ] 在 `AppReleaseRequest` 增加可选的服务到产物 ID 映射。预览和创建共用解析逻辑，检查运行成功、租户、集群、命名空间、目标服务仓库与发布权限；同一服务同时指定 tag 覆盖和产物时提示冲突。服务器从产物计算完整的 `repo@sha256:…`，贯穿预览、最终工作负载渲染、发布快照与回滚。每个服务的版本快照保留产物来源，即使运行记录后来被删除也能展示来源摘要。
- [ ] 在 `PipelineRunDetailView.vue` 每个产物旁增加「发布到应用」。选应用与服务后打开已有发布预览，显示原镜像、目标镜像和构建来源。在 `AppReleaseHistory.vue` 增加来源信息，有运行读取权限且记录存在时可返回运行详情。

**验收。** 用同一 tag 连续推送内容不同的 A、B，从 A 发版并核对工作负载实际镜像摘要。再发 B、回滚 A，验证结果仍是 A。另测一次运行并行推两个镜像、运行中断归档重投、只有构建权限的账号发版、旧版本手填 tag 发布与回滚。

## 二、按告警对象提供排障入口并记录处置

**先确定告警指向什么。** 在 `AlertView.vue` 的详情抽屉按下表生成可用操作。解析时优先使用规则显式声明的目标类型及标识，再核对告警归属、对象身份和当前用户权限。指标中的 pod、instance、job 也可能指采集器；单凭这些标签无法确认业务对象时展示原始上下文。多条来源匹配时列出候选规则供选择。

| 能确认的目标 | 提供的排障入口 |
|---|---|
| Pod 或工作负载 | 对象详情、事发时段的日志 |
| 节点或集群 | 节点详情的指标与事件，或集群概览；集群级告警允许没有命名空间 |
| 命名空间或配额 | 对应空间的配额上限与用量；租户从有权查看的租户总览进入 |
| PVC 或中间件实例 | 定位到对应卷或实例，查看卷状态或实例指标 |
| 自定义规则、外部服务、目标已删除或归属不明 | 展示告警说明、标签、注解、时间与可确认的规则来源；可继续认领和备注 |

- [ ] 对确认的 Pod 或工作负载构造日志目标，携带租户、集群 ID、命名空间、对象和绝对起止时间。默认查询触发点前后各十分钟，上界取当前时间。服务端按真实归属校验每个目标；标签仅作定位线索。没有明确对象时留在告警详情。
- [ ] 提取资源上下文定位逻辑，在 `stores/context.ts` 现有选择机制上解析目标，等待候选加载和权限校验完成，再初始化日志筛选并发起首次查询。处理已打开日志页时路由参数变化的情况。目标无权访问或已失效时停止查询，避免用上一次选择的命名空间代查。第四期复用这段逻辑。

**再交付认领和备注。**

- [ ] 以单次告警记录 ID 绑定负责人、认领时间和备注记录。备注追加保存作者、正文和时间。同一告警后续收到恢复事件时保留人工记录，同一 fingerprint 再次触发的新一轮告警拥有独立记录。
- [ ] 在 `AlertController` 和 `AlertService` 增加详情、认领和追加备注操作。按记录实际归属校验访问范围，写操作配置独立权限并纳入审计。认领使用条件更新；本人重试返回当前结果，其他人抢占时返回已有负责人。详情抽屉分开展示监控状态和人工记录。

**验收。** 昨天的工作负载告警打开昨天的日志；带 exporter Pod 标签的节点磁盘告警进入对应节点；没有命名空间的集群告警能查看集群概览；配额告警进入对应空间；自定义告警缺少目标时仍可认领。另测跨租户标签、目标已删除、无详情权限、同时认领、恢复事件与备注并发。

## 三、租户申请空间、续期与配额扩容

**用户入口。** 在 `TenantOverviewPanel.vue` 的空状态与已有分配列表提供「申请命名空间」和「我的申请」，在已分配空间行增加「申请配额扩容」。申请单以类型区分开通和扩容，共用审批列表、处理记录与审计。租户与申请人从登录身份确定。以下开通步骤沿用 `NamespaceAllocationService.create`，扩容走下方独立执行流程。

- [ ] 新增申请表，保存租户、申请人、请求内容、状态、处理人、选定集群与空间、分配记录标识、处理原因和时间。加入提交请求标识去重。申请提交和查看本人申请的权限在无命名空间分配时即可使用；管理端候选范围沿用平台管理员的集群与命名空间权限。
- [ ] 建议接口为 `/tenant/namespace-request/create`、`/mine`、`/list`、`/approve`、`/reject`，后四项同属 namespace-request 前缀。批准时管理员选已有可分配空间；需要新空间时从现有命名空间创建页建好后返回。确认页并列显示申请值和目标空间实际配额，便于管理员核对。
- [ ] 提交后进入「待处理」。批准通过条件更新锁定本次处理，进入「开通中」，调用现有分配流程，完成后记录分配 ID 并标为「已开通」。拒绝仅作用于待处理申请，并记录原因。分配冲突或失败时记录具体原因，允许重新选择并重试。对执行中断的申请，按申请 ID 关联此次分配，核对分配记录与绑定结果后继续或转为可重试；避免将其他管理员独立完成的同名分配误记为本次成功。
- [ ] 申请人回到总览即可看到状态。已开通时刷新空间候选后显示「进入命名空间」；后来收回分配时保留申请历史，入口按实时权限展示。

**验收。** 零空间普通成员提交申请，管理员处理后能进入获批空间。另测重复提交、双管理员同时批准、空间被其他租户先占、分配成功但申请状态写回前中断、跨租户读取申请，以及驳回理由对申请人可见。

**已有空间扩容。** 本期扩容指提高命名空间 ResourceQuota 的指定上限。申请、批准、实际生效分别记录。获批配额表示租户可申请的资源上限，集群可调度容量仍由节点供给决定。

- [ ] 申请人从既有分配进入，选择需要调整的资源项，查看当前上限、已用量，填写目标总量和原因。例如 CPU requests 当前 4 核、已用 3.6 核，申请提高到 8 核。按 Kubernetes 数量单位比较，保存申请时的基线。未设置上限的项单列为「未设限」，给它新增有限值应走配额配置。仅受平台管理且可写的空间提供自动执行；存在额外配额对象时注明其约束并转管理员核对。
- [ ] 管理员看到逐项的当前值、申请值与拟批准值，可部分批准并说明原因。提交与执行前均校验空间仍归属申请租户。批准端调用服务端配额更新逻辑，只合并批准项，保留其他键及 LimitRange。利用 Kubernetes resourceVersion 作条件更新；同一项基线已变化时退回重新确认。租户提交申请的权限与管理员配额写权限独立。
- [ ] 写入后回读平台管理的 default ResourceQuota，核对实际 hard 值再标为「已生效」。部分批准时逐项展示批准值与理由；失败保留原因。写入成功后若状态回写中断，重试先核对申请执行记录和实际对象，按目标总量幂等对账。分配已回收或空间已重建时终止旧单。
- [ ] 验收覆盖 CPU 从 4 核升到 8 核、部分批准、并发修改其他配额项、同一项被另一管理员调整、重复执行、空间转租及 K8s 写入失败；确认原分配关系和其他配额项保持正确。

**分配有效期与续期。** 当前 `PlatformTenantNamespace` 仅有创建时间。建议为每条租户空间分配保存获批截止时间 `expiresAt`，申请单分别保存申请期限与审批结果。测试、演示、短期项目默认选择截止日期，长期业务允许申请长期使用并由管理员确认。历史分配迁移为长期，管理员可后续复核。手工分配入口采用相同规则。

- [ ] 在空间列表、审批页和申请结果显示「长期」或明确的截止时刻与时区。到期前提醒租户负责人和管理员，首版建议提前 7 天和 1 天，按分配、截止时间与提醒档位去重。租户从空间行申请续期，说明用途和新截止日期；续期绑定原分配 ID，批准后更新期限并留存审批记录。申请待审期间沿用原截止时间。配额扩容与续期可分别发起，扩容批准只更新资源上限。
- [ ] 到期时，平台对该分配的资源访问按截止时间即时判定，保留到期记录与续期入口。覆盖列表、直接访问、已有终端和日志流；后台按分配版本撤销租户 RoleBinding，并核对实际结果。现有取消分配流程会在 RoleBinding 删除失败后仍删除分配行，到期流程应保留待清理记录、重试并向管理员展示失败。续期批准与清理任务按同一分配串行处理，恢复绑定并核对后显示可用。
- [ ] 到期保留工作负载、PVC 和命名空间，由管理员另行确认业务迁移、停用或资源回收。到期空间仍占用原分配，避免遗留数据随空间转给其他租户。到期后尚未执行的扩容单，在执行前重新核对分配有效性。
- [ ] 验收覆盖临时空间到期、长期与历史分配、提醒去重、续期待审跨过截止时刻、续期与撤权同时发生、集群离线后恢复清理，以及到期后工作负载继续运行且数据保留。

**待回收空间的两档操作。** 分配到期进入管理员的「待回收」列表，显示集群、空间、原租户、到期时间、Pod 和 PVC 数。管理员可以直接选任一档，也可以先归零、以后再删除。到期本身仅触发前述撤权流程。新增回收预览、执行、进度接口，两档分别授权。预览和执行均核对分配版本、空间 UID、系统空间保护与其他有效分配。

| 操作 | 执行方式 | 完成判据 |
|---|---|---|
| 一档「回收资源（Pod 归零）」 | 给目标空间设置独立、无 scope 的回收专用配额 `count/pods: "0"`，确认新建 Pod 的准入已受限后，按正常终止流程清理现有 Pod，包括已完成的 Pod。暂停定时任务并记录恢复所需状态。保留命名空间、工作负载定义、原配额和 PVC；预览提示容器临时存储随 Pod 释放。 | 按空间 UID 核对，完整 Pod 列表为空且回收配额持续生效，才标记「已回收资源」。仍在 Terminating 的 Pod 计入剩余数；控制器、DaemonSet 或 Operator 尝试重建时仍受同一配额约束。 |
| 二档「删除整个命名空间」 | 展示空间内对象、PVC、已知 PV 回收策略及关联的平台记录，提示卷数据可能一并删除；管理员输入空间名确认。冻结该分配并保留操作记录，以预期 UID 为前置条件提交删除。 | 持续查询到原空间消失后，核销分配、关闭待办、对账关联应用和中间件记录并保留审计。Terminating 期间显示剩余资源或 finalizer；集群不可达显示待核实。 |

- [ ] 一档采用独立配额，避免改写租户的业务配额。执行前盘点独立 Pod、流水线与有状态任务，展示中断影响；对带有 Pod 级生命周期的数据卷标明影响，涉及 PVC 自动删除或控制器清理持久数据时先核对保留措施。续期获批后，移除本次回收创建的配额、恢复已记录的调度设置，按工作负载实际就绪情况反馈；独立 Pod 和已结束任务的恢复能力在预览中说明。[Kubernetes 对象数量配额](https://kubernetes.io/docs/concepts/policy/resource-quotas/#object-count-quota)
- [ ] 二档复用 `NamespaceService.delete` 的保护规则。现有普通删除要求空间未分配，回收服务须以持久化任务占住该空间，受控解除目标到期分配，再发起删除；分配入口也检查占用记录。重试校验原 UID，遇到同名新空间立即停止。续期、回收、重新分配共享互斥检查，删除已提交时关闭续期入口。
- [ ] 验收覆盖两档直接执行、一档后升级二档、CronJob 跨调度周期、Operator 重建、已完成或卡住的 Pod、续期后恢复、重复点击、删除被 finalizer 阻塞、同名空间重建，以及集群断线后继续对账。逐档核对 PVC、分配记录和页面状态。

## 四、按名称搜索应用、工作负载和 Pod

**查询范围。** 在 `CommandPalette.vue` 保留本地菜单与操作匹配，另加资源结果区。第一版一次选择一个集群；在租户视图仅搜索该租户被分配且用户有读取权限的空间。平台视图沿用现有平台读取边界。结果包含资源类型、名称、集群、命名空间及详情定位参数。

- [ ] 在 `platform-api` 增加 `POST /resource/search`，接收集群 ID、关键词和可选资源类型。服务端确定允许查询的空间及类型；应用通过数据库按归属和名称查找，Pod、工作负载通过 `k8s-server` 的授权读取路径获取精简结果。对大集群使用有界分页和超时，返回截断标记；当扫描预算用尽时提示缩小范围。精确匹配排在前缀、包含匹配之前。
- [ ] 建议默认输入两字符后防抖 300 毫秒，最多返回 20 条，常见短名称可按回车显式查询。切换关键词、身份或集群时取消旧查询并丢弃过期响应。区分无匹配、部分来源查询失败和超时，集群断开时菜单搜索仍可用。
- [ ] 点击结果时复用第二期的上下文定位逻辑。应用按 ID 打开，工作负载按种类与名称打开，Pod 使用对应名称。每次详情读取继续执行现有权限检查；对象已删除或权限已回收时给出明确反馈。

**验收。** 用两个命名空间下的同名 Pod 验证每条结果的详情与日志归属；用只有应用读取权限的账号验证结果类型；模拟慢请求后快速切换集群，确认旧结果不会覆盖新结果。在代表性集群记录查询耗时和扫描量，再判断是否需要索引。

## 逐期上线与回归

1. 每期在 `platform-data/src/main/resources/db/migration` 添加对应增量 SQL，按仓库约定手工重放。新增接口同步登记网关权限映射和角色授权。先在带历史数据的环境验证迁移与服务启动，再升级前端。
2. 在对应模块运行相关 Maven 测试，重点扩展现有 `PipelineRunFinisherTest`、`AppReleaseServiceTest`、`AlertServiceTest`、`NamespaceAllocationServiceOneTenantTest`。每期在 `platform-web` 运行 `npm run build`，再用普通成员和平台管理员各完成对应验收步骤。
3. 若需回退，先撤回对应前端入口，再回退兼容的服务版本，保留新增业务记录。第一期额外验证旧服务对已发布摘要镜像的读取和回滚；旧服务无法处理时保留摘要解析能力，只关闭从产物新建发布的入口。

**后续议题。** 四项交付后单独评审集群部署。首项为向导表单持久化，验收覆盖刷新和关页重开后恢复节点、部署选项与当前步骤。该议题另立实施计划。
