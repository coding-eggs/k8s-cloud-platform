# 审计日志实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 `platform-api` 加一条审计轨 —— 写操作与 403 被拒请求逐条落 `platform_audit_log`，并提供平台管理员的查询页。

**Architecture:** 注解（`@Auditable`）+ AOP 管写操作（**AOP 能拿到真实业务成败**：Service 抛 `CloudPlatformException` = FAILED）；403 复用 `ResourceServerConfig` **已有的** `accessDeniedHandler`（AOP 到不了被拒请求 —— 它发生在方法调用之前）。审计记录写在**独立事务**（`REQUIRES_NEW`），整条链路 **fail-open**：审计失败绝不改变业务结果。

**Tech Stack:** Spring Boot 4.1.1 / Spring Framework 7 / Java 21 / MyBatis / Flyway / MySQL / Vue 3 + Element Plus + TypeScript

**Spec:** `docs/superpowers/specs/2026-10-13-audit-log-design.md`

## Global Constraints

从 spec 逐字抄录，**每个任务的要求都隐含包含本节**：

- **范围**：写操作 + 被拒请求（403）。**不含**变更前后值、**不含**读操作、**不存**请求体全文。
- **可见范围**：只有平台管理员。表结构与查询接口**不加租户维度**。
- **写操作判据**：注解声明。**`platform_permission` 不加任何字段**。⚠️ 本平台查询也走 POST，**绝不可按 HTTP method 判断写操作**。
- **401 不记**（`authenticationEntryPoint` 那一行不得改动）。
- **写入契约**：同步写 + **fail-open**。审计写失败只 `log.error`，业务照常返回。
- **只审 platform-api 层**，不覆盖 k8s-server。
- **不做**：覆盖护栏测试、分区、自动清理、租户可见视图、`detail` 富化列。
- **动作码命名**：`<resource>:<verb>`，常量集中在 `AuditAction`。
- **迁移惯例**：显式 id + `ON DUPLICATE KEY UPDATE` 幂等；角色关联按**显式 id 列表**，**绝不用 LIKE**（id 里的 `_` 是 LIKE 单字符通配符）。
- **部署顺序**：**先重放迁移，再起新构建** —— `PermissionCrossCheckRunner` fail-closed，无权限行的新端点会让 platform-api 拒绝启动。
- **新增 `@Auditable` 的动作不需要动迁移、不需要动权限表**（这是注解方案相对「权限表加列」的直接收益）。
- 新建文件的包路径：后端注解族 `com.coding.platformapi.audit`；实体/Mapper 归 `platform-data`。

## 两处 spec 偏离（写计划时发现，已回写 spec §6 / §2）

1. **去掉 `POST /audit/get`** —— spec §6 列了它，但 §7 描述「详情 = 行展开」，而列表本来就返回全部 18 个字段 ⇒ 该端点纯冗余。权限行从 4 条变 **3 条**。
2. **引入 `AuditWriter` 独立 bean** —— 写方法若留在 `AuditService` 内由同类方法自调用，Spring 代理被绕过，`REQUIRES_NEW` **静默失效**（`PermissionRowWriter` 的注释记着同一个坑）。故按该先例拆出独立 bean。

```sql
-- ============================================================================================
-- S0.1 审计日志：建表 + 权限行（3 行）+ admin 角色关联
-- ============================================================================================
-- 背景：平台对写操作零留痕。本批新增 platform_audit_log，以及 platform-api 的 /audit/** 两端点。
-- 设计全文见 docs/superpowers/specs/2026-10-13-audit-log-design.md。
--
-- 权限码：
--   · platform:audit:read   —— 审计列表（写操作 + 403 被拒记录，含筛选与游标分页）
--   · platform:audit:purge  —— 按时间范围删除
--   · platform:page:audit   —— 前端页面可见性（Page 域）
-- 只给 admin：审计是平台管理面，无租户对应页面（spec「可见范围 = 只有平台管理员」）。
--
-- ⚠️ 部署顺序：先重放本文件再起新构建 —— 无行的新端点会被 PermissionCrossCheckRunner 拒启（fail-closed）。
-- ⚠️ 重放后需重新登录或等权限缓存 TTL（30s）：token 里已无权限码，闭包在请求期现算。
-- 幂等：表用 IF NOT EXISTS；权限行显式 id + ODKU；角色关联按【显式 id 列表】，不用 LIKE
--（id 里的 `_` 是 LIKE 的单字符通配符，V2026_10_08_5 已踩过）。
-- ============================================================================================

CREATE TABLE IF NOT EXISTS `platform_audit_log` (
  `id`                 bigint       NOT NULL AUTO_INCREMENT,
  `occurred_at`        datetime(3)  NOT NULL COMMENT '发生时刻（毫秒）',
  `actor_username`     varchar(64)  NOT NULL COMMENT '操作者账号；取不到身份时记字面量 unknown（不记 NULL）',
  `actor_display_name` varchar(64)           DEFAULT NULL COMMENT '冗余存：账号改名/删除后记录仍可读',
  `tenant_id`          varchar(26)           DEFAULT NULL COMMENT '被操作的租户（代操作时是目标租户；平台侧无租户操作为 NULL）',
  `cluster_id`         varchar(26)           DEFAULT NULL,
  `namespace`          varchar(63)           DEFAULT NULL,
  `action`             varchar(64)           DEFAULT NULL COMMENT '写操作=动作码 <resource>:<verb>；DENIED=被拒的权限码。语义随 result 变',
  `target_name`        varchar(253)          DEFAULT NULL COMMENT '目标对象名；DENIED 为空（拒绝发生在方法调用前）',
  `result`             varchar(16)  NOT NULL COMMENT 'SUCCESS / FAILED / DENIED',
  `error_code`         varchar(32)           DEFAULT NULL COMMENT 'FAILED 的业务码',
  `error_msg`          varchar(512)          DEFAULT NULL COMMENT 'FAILED 的业务 msg',
  `http_method`        varchar(8)            DEFAULT NULL COMMENT '仅 DENIED 有值',
  `request_path`       varchar(512)          DEFAULT NULL COMMENT '仅 DENIED 有值',
  `client_ip`          varchar(45)           DEFAULT NULL COMMENT '兼容 IPv6',
  `user_agent`         varchar(256)          DEFAULT NULL COMMENT '安全排查用',
  `duration_ms`        int                   DEFAULT NULL COMMENT '耗时；DENIED 为 NULL',
  PRIMARY KEY (`id`) USING BTREE,
  KEY `idx_occurred`   (`occurred_at`, `id`) USING BTREE,
  KEY `idx_actor`      (`actor_username`, `occurred_at`) USING BTREE,
  KEY `idx_cluster_ns` (`cluster_id`, `namespace`, `occurred_at`) USING BTREE,
  KEY `idx_result`     (`result`, `occurred_at`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci ROW_FORMAT=DYNAMIC
  COMMENT='平台审计日志（写操作 + 403 被拒请求）';

-- ===== 权限行：API 域 2 行 + Page 域 1 行 =====
INSERT INTO platform_permission (id, domain, resource, action, code, description) VALUES
 ('perm_audit_list','API','/audit/list','POST','platform:audit:read',
  '审计日志列表（写操作 + 403 被拒；筛选与游标分页）'),
 ('perm_audit_purge','API','/audit/purge','POST','platform:audit:purge',
  '按时间范围删除审计日志'),
 ('perm_page_audit','Page','/audit','view','platform:page:audit',
  '审计日志页可见性')
ON DUPLICATE KEY UPDATE description=VALUES(description), resource=VALUES(resource), action=VALUES(action);

-- ===== 角色关联：admin 全给（显式 id 列表） =====
INSERT INTO platform_role_permission (id, role_id, permission_id) VALUES
 ('rp_admin_audit_list','builtin_role_admin','perm_audit_list'),
 ('rp_admin_audit_purge','builtin_role_admin','perm_audit_purge'),
 ('rp_admin_page_audit','builtin_role_admin','perm_page_audit')
ON DUPLICATE KEY UPDATE permission_id=VALUES(permission_id);

-- tenant-admin / tenant-member 有意不给：审计是平台管理面。
```

**两条踩过的坑**（改这个文件时别再犯）：
1. **jshell 每个语句是独立 snippet，失败不会中断后续** —— 校验语句写在 `execute` 之后时，
   前一条抛异常它照样往下跑，于是"成功"是假象。所以把整个流程放进**一个方法**里，只有 `execute` 返回才打印成功标记。
2. **MySQL 只把「`--` 后跟空白」当注释**。注释行写成 `--（中文括号…` 会被当 SQL 解析而报语法错误。
   写注释时 `--` 后面一律留一个空格（既有迁移把这类括号写在行内，所以历史文件没踩到）。

```java
package com.coding.data.models.system;

import lombok.Data;

import java.util.Date;

/**
 * 平台审计日志（表 platform_audit_log）。
 *
 * <p>设计见 docs/superpowers/specs/2026-10-13-audit-log-design.md。
 * <p><b>审计记录必须自包含</b>：一旦落库就不得依赖其他表才读得懂，所以 actorDisplayName 冗余存。
 * <p>{@code action} 的语义随 {@code result} 变：写操作存动作码 {@code <resource>:<verb>}，
 * {@code DENIED} 存被拒的权限码。
 * <p>{@code id} 用自增（非本仓惯用的 ULID）：追加型日志表用自增，插入更省、时间序扫描更顺。
 */
@Data
public class PlatformAuditLog {

    private Long id;

    private Date occurredAt;

    private String actorUsername;

    private String actorDisplayName;

    private String tenantId;

    private String clusterId;

    private String namespace;

    /** 写操作 = 动作码；DENIED = 被拒的权限码 */
    private String action;

    private String targetName;

    /** SUCCESS / FAILED / DENIED（见 com.coding.platformapi.audit.AuditResult） */
    private String result;

    private String errorCode;

    private String errorMsg;

    private String httpMethod;

    private String requestPath;

    private String clientIp;

    private String userAgent;

    private Integer durationMs;
}
```

```java
package com.coding.platformapi.audit;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

/**
 * 标记一个**写操作**的 Service 方法，由 {@link AuditAspect} 记录审计。
 *
 * <p>设计见 docs/superpowers/specs/2026-10-13-audit-log-design.md。
 *
 * <p><b>标在 Service 层，不标 Controller</b>：业务全在 Service（见 docs/development/backend-layering.md），
 * 而且只有 Service 方法抛的 {@code CloudPlatformException} 才是真正的业务失败。
 *
 * <p><b>不要标在流式方法上</b>（Pod/Node 日志流等）—— 那会把流式响应拖进审计路径。
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Auditable {

    /**
     * 动作码，取 {@link AuditAction} 里的常量（如 {@code AuditAction.WORKLOAD_DELETE}）。
     */
    String action();

    /**
     * 目标对象名的 SpEL，如 {@code "#name"} / {@code "#req.name"}。
     * 留空则按命名约定探测（方法参数名或单个 DTO 参数的一级字段名 {@code name}）。
     */
    String target() default "";

    /**
     * 上下文（tenantId / clusterId / namespace）的 SpEL，逗号分隔，按顺序填充。
     * 留空则按约定探测同名参数/字段。
     */
    String scope() default "";
}
```

```java
package com.coding.platformapi.audit;

import lombok.extern.slf4j.Slf4j;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.reflect.MethodSignature;
import org.springframework.core.DefaultParameterNameDiscoverer;
import org.springframework.core.ParameterNameDiscoverer;
import org.springframework.expression.Expression;
import org.springframework.expression.spel.standard.SpelExpressionParser;
import org.springframework.expression.spel.support.StandardEvaluationContext;
import org.springframework.stereotype.Component;
import org.springframework.util.StringUtils;

import java.lang.reflect.Method;

/**
 * 从被切的 Service 方法上抽出「目标对象名」与「上下文」。
 *
 * <p><b>显式优先、隐式兜底</b>：注解给了 SpEL 就用 SpEL；没给就按命名约定探测 ——
 * 方法参数名，或**单个 DTO 参数的一级字段名**（{@code name} / {@code tenantId} /
 * {@code clusterId} / {@code namespace}）。这正是本平台 DTO 的统一形状，所以简单场景零配置。
 *
 * <p><b>探测深度只到一级，不递归</b>：嵌套结构（如 {@code #req.spec.foo}）必须走显式 SpEL ——
 * 规则简单可预测比"猜得深"更重要（spec §3.2）。
 *
 * <p><b>求值失败不致命</b>：任何异常都降级为 null + 一条 warn，绝不让业务方法因注解写错而挂（spec §3.3）。
 */
@Slf4j
@Component
public class AuditTargetResolver {

    private static final ParameterNameDiscoverer NAME_DISCOVERER = new DefaultParameterNameDiscoverer();

    private static final String FIELD_NAME = "name";
    private static final String FIELD_TENANT_ID = "tenantId";
    private static final String FIELD_CLUSTER_ID = "clusterId";
    private static final String FIELD_NAMESPACE = "namespace";

    private final SpelExpressionParser parser = new SpelExpressionParser();

    /** 审计上下文三元组；任一取不到即为 null。 */
    public record Scope(String tenantId, String clusterId, String namespace) {
    }

    /**
     * 目标对象名：SpEL 优先，否则探测名为 {@code name} 的参数 / DTO 一级字段。
     */
    public String resolveTarget(ProceedingJoinPoint pjp, String spel) {
        if (StringUtils.hasText(spel)) {
            return asString(evaluate(pjp, spel));
        }
        return probe(pjp, FIELD_NAME);
    }

    /**
     * 上下文三元组：SpEL 优先（按 tenantId, clusterId, namespace 顺序取逗号分隔的多个表达式），
     * 否则各自按名探测。
     */
    public Scope resolveScope(ProceedingJoinPoint pjp, String spel) {
        if (StringUtils.hasText(spel)) {
            String[] parts = spel.split(",");
            return new Scope(
                    parts.length > 0 ? asString(evaluate(pjp, parts[0].trim())) : null,
                    parts.length > 1 ? asString(evaluate(pjp, parts[1].trim())) : null,
                    parts.length > 2 ? asString(evaluate(pjp, parts[2].trim())) : null);
        }
        return new Scope(probe(pjp, FIELD_TENANT_ID), probe(pjp, FIELD_CLUSTER_ID), probe(pjp, FIELD_NAMESPACE));
    }

    // ------------------------------------------------------------------ 内部

    private Object evaluate(ProceedingJoinPoint pjp, String spel) {
        try {
            Expression expression = parser.parseExpression(spel);
            StandardEvaluationContext ctx = new StandardEvaluationContext();
            String[] paramNames = paramNames(pjp);
            Object[] args = pjp.getArgs();
            for (int i = 0; i < args.length; i++) {
                String pname = paramNames != null && i < paramNames.length ? paramNames[i] : "arg" + i;
                ctx.setVariable(pname, args[i]);
            }
            return expression.getValue(ctx);
        } catch (Exception e) {
            // 注解写错不该让生产接口挂掉（fail-open 同样适用于 SpEL）
            log.warn("审计注解 SpEL 求值失败，字段降级为 null：spel={} err={}", spel, e.getMessage());
            return null;
        }
    }

    /**
     * 按名探测：先看与方法参数同名的字符串参数，再看单个 DTO 参数的一级字段。
     */
    private String probe(ProceedingJoinPoint pjp, String field) {
        try {
            String[] paramNames = paramNames(pjp);
            Object[] args = pjp.getArgs();
            for (int i = 0; i < args.length; i++) {
                Object arg = args[i];
                if (arg == null) {
                    continue;
                }
                if (arg instanceof String s) {
                    String pname = paramNames != null && i < paramNames.length ? paramNames[i] : null;
                    if (field.equals(pname)) {
                        return s;
                    }
                } else if (isPlainPojo(arg)) {
                    String v = readGetter(arg, field);
                    if (v != null) {
                        return v;
                    }
                }
            }
        } catch (Exception e) {
            log.warn("审计上下文探测失败，字段降级为 null：field={} err={}", field, e.getMessage());
        }
        return null;
    }

    private String[] paramNames(ProceedingJoinPoint pjp) {
        MethodSignature sig = (MethodSignature) pjp.getSignature();
        Method method = sig.getMethod();
        return NAME_DISCOVERER.getParameterNames(method);
    }

    /** 只对平台自己的类做反射读字段，跳过 JDK / Spring 类型（避免在无关对象上乱找 getter）。 */
    private boolean isPlainPojo(Object o) {
        String n = o.getClass().getName();
        return n.startsWith("com.coding.");
    }

    private String readGetter(Object target, String field) {
        String getter = "get" + Character.toUpperCase(field.charAt(0)) + field.substring(1);
        try {
            Object v = target.getClass().getMethod(getter).invoke(target);
            return v == null ? null : String.valueOf(v);
        } catch (ReflectiveOperationException e) {
            return null;
        }
    }

    private String asString(Object v) {
        return v == null ? null : String.valueOf(v);
    }
}
```

```java
package com.coding.platformapi.audit;

import com.coding.data.mapper.system.PlatformAuditLogMapper;
import com.coding.data.models.system.PlatformAuditLog;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

/**
 * 审计记录的**独立事务**写入点。
 *
 * <p><b>为什么单独一个 bean</b>：Spring 的事务代理只在**跨 bean 调用**时生效。
 * 若把 {@code write} 放在 {@code AuditService} 里由同类方法调用，{@code REQUIRES_NEW} 会被静默绕过 ——
 * 那时审计记录会加入业务事务，业务一回滚就把记录一起带走（恰好丢掉最想留的那条 FAILED）。
 * 同族先例见 {@code PermissionRowWriter} 的类注释。
 *
 * <p>{@code REQUIRES_NEW} 的第二个作用：审计写失败不会污染业务事务（不会把它标记成 rollback-only），
 * 这是 fail-open 能成立的前提。
 */
@Component
@RequiredArgsConstructor
public class AuditWriter {

    private final PlatformAuditLogMapper mapper;

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void write(PlatformAuditLog record) {
        mapper.insert(record);
    }
}
```

```java
package com.coding.platformapi.audit;

import jakarta.servlet.http.HttpServletRequest;

import java.util.Set;

/**
 * 403 被拒请求的权限码载体。
 *
 * <p>{@code AccessDeniedException} 本身**不带**权限码，所以由
 * {@code PermissionAuthorizationManager} 在 deny 分支把它塞进 request attribute，
 * 再由 {@code ResourceServerConfig} 的 {@code accessDeniedHandler} 读出来落审计。
 * 这样审计能回答「用户想做什么」，而不只是「调了哪个 URL」。
 *
 * <p>未认证（401）不会有这个 attribute —— 那条路径有意不记（spec §9）。
 */
public final class AuditDenied {

    /** request attribute 名 */
    public static final String ATTR_DENIED_CODES = "com.coding.audit.deniedCodes";

    private AuditDenied() {
    }

    /** 把被判的权限码集合塞进请求（要求集合非空；空集没有记录价值） */
    public static void mark(HttpServletRequest request, Set<String> codes) {
        if (codes != null && !codes.isEmpty()) {
            request.setAttribute(ATTR_DENIED_CODES, String.join(",", codes));
        }
    }

    /** 读出被拒的权限码；没有则 null */
    public static String codesOf(HttpServletRequest request) {
        Object v = request.getAttribute(ATTR_DENIED_CODES);
        return v == null ? null : String.valueOf(v);
    }
}
```

```java
package com.coding.platformapi.services;

import com.coding.data.mapper.system.PlatformAuditLogMapper;
import com.coding.data.models.system.PlatformAuditLog;
import com.coding.data.models.system.PlatformAuditLogQuery;
import com.coding.data.models.system.TokenUserInfo;
import com.coding.platformapi.audit.AuditDenied;
import com.coding.platformapi.audit.AuditResult;
import com.coding.platformapi.audit.AuditWriter;
import com.coding.platformapi.security.AuthContext;
import jakarta.servlet.http.HttpServletRequest;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

import java.util.Date;
import java.util.List;

/**
 * 审计记录的门面：**fail-open 包装** + 查询 + 拒绝记录。
 *
 * <p>记录**组装**不在这里 —— 写操作的组装在 {@code AuditAspect}（它才有 join point），
 * 拒绝记录的组装在 {@link #recordDenied}（它拿到的是 HTTP 请求）。
 * 本类只负责「怎么把记录安全地写下去」。
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class AuditService {

    /**
     * 身份取不到时记的字面量（不记 NULL —— 与「平台侧无租户操作」的 NULL 语义区分开）。
     * <p><b>public</b>：{@code AuditAspect} 在 {@code ...audit} 包，是本类的跨包使用者。
     */
    public static final String UNKNOWN_ACTOR = "unknown";

    private static final int DEFAULT_LIMIT = 50;
    private static final int MAX_LIMIT = 200;

    private final AuditWriter writer;
    private final PlatformAuditLogMapper mapper;
    private final AuthContext authContext;

    /**
     * fail-open：审计写不进去只记错误日志，**绝不改变业务结果**（spec「写入契约」）。
     */
    public void record(PlatformAuditLog record) {
        try {
            writer.write(record);
        } catch (Exception e) {
            log.error("审计写入失败 action={} result={} path={}",
                    record.getAction(), record.getResult(), record.getRequestPath(), e);
        }
    }

    /**
     * 记录一条 403 被拒请求。
     *
     * <p><b>绝不能抛</b>：这是唯一一处「审计失败会改变用户可见结果」的位置 ——
     * 它一抛，403 就变成 500，把「权限不足」伪装成「服务故障」，还掩盖了真实原因（spec §5.4）。
     */
    public void recordDenied(HttpServletRequest request) {
        try {
            TokenUserInfo user = authContext.current();
            PlatformAuditLog r = new PlatformAuditLog();
            r.setOccurredAt(new Date());
            r.setActorUsername(user != null && StringUtils.hasText(user.getUsername())
                    ? user.getUsername() : UNKNOWN_ACTOR);
            r.setActorDisplayName(user == null ? null : user.getDisplayName());
            r.setTenantId(authContext.hatTenantId());
            r.setAction(AuditDenied.codesOf(request));
            r.setResult(AuditResult.DENIED.name());
            r.setHttpMethod(request.getMethod());
            r.setRequestPath(request.getRequestURI());
            r.setClientIp(clientIp(request));
            r.setUserAgent(request.getHeader("User-Agent"));
            writer.write(r);
        } catch (Exception e) {
            log.error("审计（拒绝）写入失败 path={}", request.getRequestURI(), e);
        }
    }

    /** 查询：limit 由本层钳制，调用方不必关心上限 */
    public List<PlatformAuditLog> query(PlatformAuditLogQuery q) {
        clamp(q);
        return mapper.query(q);
    }

    /** 删除：闭开区间 [from, to)；返回实际删除行数 */
    public int purge(Date from, Date to) {
        return mapper.deleteByTimeRange(from, to);
    }

    private void clamp(PlatformAuditLogQuery q) {
        Integer limit = q.getLimit();
        if (limit == null || limit <= 0) {
            q.setLimit(DEFAULT_LIMIT);
        } else if (limit > MAX_LIMIT) {
            q.setLimit(MAX_LIMIT);
        }
    }

    /**
     * 客户端 IP：优先 X-Forwarded-For 的第一个（平台通常经网关），退化到 remoteAddr。
     */
    private String clientIp(HttpServletRequest request) {
        String forwarded = request.getHeader("X-Forwarded-For");
        if (StringUtils.hasText(forwarded)) {
            int comma = forwarded.indexOf(',');
            return (comma > 0 ? forwarded.substring(0, comma) : forwarded).trim();
        }
        return request.getRemoteAddr();
    }
}
```

```java
 * 写操作的审计切面：包住带 {@link Auditable} 的 Service 方法。
 *
 * <h3>⚠️ 为什么 {@code @Order(0)} 是必须的</h3>
 * 本仓 {@code @EnableTransactionManagement} + Service 方法级 {@code @Transactional} 真在用。
 * 事务通知的默认 order 是 {@code Ordered.LOWEST_PRECEDENCE}，而**值越小越靠外** ——
 * {@code @Order(0)} 让本切面排在事务通知**外面**，于是记录时机在业务**提交/回滚之后**，
 * 看到的是真实结果。若排在里面，会记下一条随后被回滚的 SUCCESS（spec §5.1）。
 *
 * <h3>结果语义</h3>
 * Service 方法正常返回 = {@code SUCCESS}；抛异常 = {@code FAILED}（典型是 {@link CloudPlatformException}，
 * 带上它的业务码与 msg）。异常**原样抛回**，切面不改业务语义。
 *
 * <h3>为什么用 @Around 而不是 @AfterThrowing</h3>
 * 成功与失败必须是**同一条记录**里的不同 result，而不是两条互不相干的记录 ——
 * 否则「重试/重发」会在表里留下两条，读的人分不清。
 */
@Slf4j
@Aspect
@Component
@Order(0)
@RequiredArgsConstructor
public class AuditAspect {

    private final AuditService auditService;
    private final AuthContext authContext;
    private final AuditTargetResolver targetResolver;

    @Around("@annotation(auditable)")
    public Object around(ProceedingJoinPoint pjp, Auditable auditable) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            Object result = pjp.proceed();
            auditService.record(build(pjp, auditable, AuditResult.SUCCESS, null, start));
            return result;
        } catch (Throwable t) {
            auditService.record(build(pjp, auditable, AuditResult.FAILED, t, start));
            throw t;
        }
    }

    private PlatformAuditLog build(ProceedingJoinPoint pjp, Auditable auditable,
                                   AuditResult result, Throwable error, long start) {
        PlatformAuditLog r = new PlatformAuditLog();
        r.setOccurredAt(new Date());
        r.setAction(auditable.action());
        r.setResult(result.name());
        r.setDurationMs((int) (System.currentTimeMillis() - start));

        TokenUserInfo user = authContext.current();
        r.setActorUsername(user != null && StringUtils.hasText(user.getUsername())
                ? user.getUsername() : AuditService.UNKNOWN_ACTOR);
        r.setActorDisplayName(user == null ? null : user.getDisplayName());

        r.setTargetName(targetResolver.resolveTarget(pjp, auditable.target()));

        AuditTargetResolver.Scope scope = targetResolver.resolveScope(pjp, auditable.scope());
        // tenantId：参数里的优先（代操作时那是「被操作的租户」），退而取 token 租户帽（spec §5.6）
        r.setTenantId(scope.tenantId() != null ? scope.tenantId() : authContext.hatTenantId());
        r.setClusterId(scope.clusterId());
        r.setNamespace(scope.namespace());

        if (error instanceof CloudPlatformException cpe) {
            r.setErrorCode(String.valueOf(cpe.getCode()));
            r.setErrorMsg(cpe.getMsg());
        } else if (error != null) {
            r.setErrorMsg(truncate(error.getClass().getSimpleName() + ": " + error.getMessage(), 512));
        }

        // 非 HTTP 线程（将来的定时任务）取不到请求上下文 → 这三项留空，绝不抛（spec §5.2）
        var attrs = RequestContextHolder.getRequestAttributes();
        if (attrs instanceof ServletRequestAttributes sra) {
            r.setClientIp(sra.getRequest().getRemoteAddr());
            r.setUserAgent(sra.getRequest().getHeader("User-Agent"));
        }
        return r;
    }

    private String truncate(String s, int max) {
        if (s == null) {
            return null;
        }
        return s.length() <= max ? s : s.substring(0, max);
    }
}
```

> **⚠️ 实施期偏离（TDD 抓到，已按下面的写法落地）**：上面这版把成功路径的 `auditService.record`
> 放在业务 `try` **里面**，于是「审计失败不影响业务」这条契约**完全寄存在 `AuditService` 的 try/catch 里** ——
> 谁把那个 try/catch 去掉，本切面会静默地开始破坏业务（成功路径的记录调用一旦抛出，业务返回值就丢了）。
> `AuditFailureNeverBreaksBusiness` 正是把这一点测出来了。落地版改为：

```vue
<script setup lang="ts">
/**
 * 审计日志页（平台管理面，仅 admin）。
 *
 * - 游标分页：审计表持续追加，offset 会漏读/重读，所以用「上一页最后一条的 (occurredAt, id)」做游标（spec §7）
 * - 详情 = 行展开，不额外开后端端点（列表已返回全部字段）
 * - 门控走 pageCodes（页面可见性），不要写字面量
 */
import { onMounted, reactive, ref } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import { auditApi } from '@/api'
import type { AuditLog, AuditQuery } from '@/types'

const rows = ref<AuditLog[]>([])
const loading = ref(false)
const cursor = ref<{ occurredAt: string; id: number } | null>(null)
/** 上一页是否满页；不满说明已到底（游标语义下没有「总数」可问） */
const hasMore = ref(false)

const PAGE_SIZE = 50

const filters = reactive<AuditQuery>({
  from: null,
  to: null,
  actorUsername: null,
  clusterId: null,
  namespace: null,
  result: null,
  action: null,
})

const RESULT_OPTIONS = [
  { value: 'SUCCESS', label: '成功' },
  { value: 'FAILED', label: '失败' },
  { value: 'DENIED', label: '被拒' },
]

function resultType(r: AuditLog['result']): 'success' | 'danger' | 'warning' {
  if (r === 'SUCCESS') return 'success'
  if (r === 'FAILED') return 'danger'
  return 'warning'
}

function fmtDate(v?: string | null): string {
  if (!v) return '—'
  return new Date(v).toLocaleString('zh-CN')
}

/** 动作码/目标列：写操作看动作码+目标对象，DENIED 看被拒权限码+请求路径 */
function actionText(row: AuditLog): string {
  if (row.result === 'DENIED') {
    return `${row.action ?? '（无权限码）'} ${row.httpMethod ?? ''} ${row.requestPath ?? ''}`.trim()
  }
  return `${row.action ?? '—'}${row.targetName ? ' → ' + row.targetName : ''}`
}

async function load(reset = false): Promise<void> {
  if (reset) {
    cursor.value = null
    hasMore.value = false
  }
  loading.value = true
  try {
    const q: AuditQuery = { ...filters, limit: PAGE_SIZE }
    if (cursor.value) {
      q.cursorOccurredAt = cursor.value.occurredAt
      q.cursorId = cursor.value.id
    }
    const page = await auditApi.list(q)
    // 游标分页下没有「上一页」：首查替换、后续追加，往前翻靠重新查询
    rows.value = reset ? page : [...rows.value, ...page]
    hasMore.value = page.length === PAGE_SIZE
    const last = page[page.length - 1]
    cursor.value = last ? { occurredAt: last.occurredAt, id: last.id } : null
  } finally {
    loading.value = false
  }
}

async function purge(): Promise<void> {
  if (!filters.from || !filters.to) {
    ElMessage.warning('请先在上方选择时间范围')
    return
  }
  await ElMessageBox.confirm(
    `将删除 ${fmtDate(filters.from)} 至 ${fmtDate(filters.to)} 之间的全部审计记录，不可恢复。`,
    '删除审计记录',
    { type: 'warning' },
  )
  const deleted = await auditApi.purge(filters.from, filters.to)
  ElMessage.success(`已删除 ${deleted} 条`)
  void load(true)
}

onMounted(() => void load(true))
</script>

<template>
  <div>
    <div class="page-header">
      <div>
        <h2 class="ph-title">审计日志</h2>
        <p class="ph-desc">写操作与 403 被拒请求的留痕；按时间倒序，游标分页</p>
      </div>
      <el-button type="danger" plain @click="purge">按时间范围删除</el-button>
    </div>

    <div class="panel filters">
      <el-date-picker v-model="filters.from" type="datetime" value-format="YYYY-MM-DDTHH:mm:ss"
                      placeholder="起始时间" />
      <el-date-picker v-model="filters.to" type="datetime" value-format="YYYY-MM-DDTHH:mm:ss"
                      placeholder="结束时间" />
      <el-input v-model="filters.actorUsername" placeholder="操作者账号" clearable />
      <el-input v-model="filters.clusterId" placeholder="集群 ID" clearable />
      <el-input v-model="filters.namespace" placeholder="命名空间" clearable />
      <el-select v-model="filters.result" placeholder="结果" clearable>
        <el-option v-for="o in RESULT_OPTIONS" :key="o.value" :label="o.label" :value="o.value" />
      </el-select>
      <el-input v-model="filters.action" placeholder="动作码 / 权限码" clearable />
      <el-button type="primary" @click="load(true)">查询</el-button>
    </div>

    <el-table v-loading="loading" :data="rows" stripe>
      <el-table-column type="expand">
        <template #default="{ row }">
          <div class="detail">
            <div><span class="k">错误码</span>{{ row.errorCode ?? '—' }}</div>
            <div><span class="k">错误信息</span>{{ row.errorMsg ?? '—' }}</div>
            <div><span class="k">请求路径</span>{{ row.requestPath ?? '—' }}</div>
            <div><span class="k">User-Agent</span>{{ row.userAgent ?? '—' }}</div>
            <div><span class="k">来源 IP</span>{{ row.clientIp ?? '—' }}</div>
            <div><span class="k">耗时</span>{{ row.durationMs != null ? row.durationMs + ' ms' : '—' }}</div>
          </div>
        </template>
      </el-table-column>
      <el-table-column label="时间" width="180">
        <template #default="{ row }">{{ fmtDate(row.occurredAt) }}</template>
      </el-table-column>
      <el-table-column label="操作者" width="180">
        <template #default="{ row }">
          {{ row.actorDisplayName || row.actorUsername }}
          <span v-if="row.actorDisplayName" class="muted">{{ row.actorUsername }}</span>
        </template>
      </el-table-column>
      <el-table-column label="结果" width="90">
        <template #default="{ row }">
          <el-tag size="small" :type="resultType(row.result)" effect="plain">{{ row.result }}</el-tag>
        </template>
      </el-table-column>
      <el-table-column prop="tenantId" label="租户" width="120" show-overflow-tooltip />
      <el-table-column prop="clusterId" label="集群" width="120" show-overflow-tooltip />
      <el-table-column prop="namespace" label="命名空间" width="140" show-overflow-tooltip />
      <el-table-column label="动作 / 目标" min-width="260" show-overflow-tooltip>
        <template #default="{ row }">
          <code class="mono">{{ actionText(row) }}</code>
        </template>
      </el-table-column>
    </el-table>

    <div class="pager">
      <el-button :disabled="!cursor || !hasMore || loading" @click="load(false)">加载更多</el-button>
    </div>
  </div>
</template>
```
