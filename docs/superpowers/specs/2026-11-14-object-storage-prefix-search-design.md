# 对象存储对象浏览：当前目录前缀搜索（设计）

> 2026-11-14。改动只在 `platform-web`，后端与 k8s-server 不改。

## 1. 目标

对象浏览页（[ObjectStorageView.vue](../../../platform-web/src/views/ObjectStorageView.vue)）加一个搜索框，
在**当前目录内**按 key 前缀找对象，结果扁平列出（可跨子目录），不牺牲性能。

## 2. 现状与约束

- 浏览是文件浏览器式下钻：`/object-storage/objects/list` 传 `prefix` + `delimiter="/"`，
  当前层文件进 `items`、子目录进 `folders`。
- 同一接口**不传 `delimiter` 时是递归扁平列举**，`prefix` + `after`（游标）+ `maxKeys` 分页已具备
  （[SeaweedS3Service.java:301](../../../k8s-server/src/main/java/com/coding/k8sserver/services/SeaweedS3Service.java:301)）。
- S3 只有前缀匹配，没有子串检索；不做全桶扫描，所以搜索开销 = 匹配到的那一段 key 的列举量。

## 3. 方案

搜索 = 复用现有列对象接口，切到扁平模式：

```
prefix    = objPrefix + 输入（trim 后）   // objPrefix 以 "/" 结尾或为空
delimiter = 不传                          // → 递归扁平
after     = 当前页游标（沿用 objCursors）
maxKeys   = 200
```

前端过滤掉 `isDir()` 的目录占位对象（key 以 `/` 结尾），只展示文件。

**考虑过但没有采用：**

- 全桶绝对前缀（搜索框忽略当前目录）：用户明确要求只搜当前目录。
- 保留 `delimiter` 的「前缀跳转」：跨层看不到文件，不是搜索。

## 4. 交互

- 搜索框放在对象浏览工具栏（面包屑右侧，与上传/上一级/刷新同排），placeholder
  「在当前目录下按前缀搜索（区分大小写）」。
- 输入 300ms 防抖自动搜索；回车立即搜索。
- 搜索中：表格只显示文件行，名称列为**相对当前目录的路径**（如 `11/01/app.log`），
  匹配到的前缀部分加粗；大小/修改时间/下载/删除不变。
- 分页沿用现有游标栈；搜索词变化或重新搜索时重置到第 1 页。
- 清空搜索框 → 回到当前目录的目录视图（重新按 `delimiter` 列）。
- 换目录（面包屑 / 上一级 / 点文件夹）→ 清空搜索。
- 空结果文案：「当前目录下没有以 xxx 开头的对象」。
- 搜索期间上传仍上传到当前目录；上传成功后清空搜索并回到目录视图，保证新文件可见。
- 搜索期间删除对象：按完整 key 删，删完重跑当前搜索。

## 5. 不做什么

- 不做跨桶搜索、不做对象内容全文检索。
- 不做「搜索整个桶」开关（用户已排除）。
- 不改后端接口、不加新端点、不加索引。
- 不动桶列表、凭据、配额等其它区域。

## 6. 性能

- 每次搜索只列举 `objPrefix + 输入` 前缀下的 key，不递归整桶；单页上限 200，游标翻页。
- 请求随输入防抖，且丢弃过期响应（后发先至时以最后一次为准）。

## 7. 验证

- `npm run build`（或项目现有前端检查）通过。
- 浏览器 preview 用假 token + XHR stub 验证：搜索→扁平结果、翻页、清空回目录、换目录清空搜索、
  目录占位对象被过滤、空结果文案（参照「UI preview 验证法」）。
- 后端无改动，不需要服务端测试。
